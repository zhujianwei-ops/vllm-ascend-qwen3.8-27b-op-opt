## Shape 与条件 Roofline

以下“算力利用率”按算子逻辑工作量计算，并非模型级 MFU。沿用 README 的参考分母：INT8=1.12 POP/s、BF16=560 TFLOP/s、带宽=3.2 TB/s；README 中整机、板卡、逻辑 Device 的映射尚未完全确认，结果只用于同口径比较。

每次矩阵乘用 `F=2*M*K*N`，包含 NZ 权重实际 shape 的一次读取、输入、输出和 scale 的一次传输，得到 `B_model`。`U_compute=ΣF/(P_peak*Σt)`，`MBU_model=ΣB_model/(BW_peak*Σt)`，`T_lower=Σ max(F/P_peak,B_model/BW_peak)`。缓存、tiling 重读和中间数据不在此模型内，故不是硬件 HBM 读写测量，也不是严格可达的优化极限。

本机 CANN `viewer/runtime_report.py::cube_usage` 计算 `cube_utilization` 时，主要用 `aic_total_cycles / (频率*核数*任务时长)`，没有将 MAC ratio 作为乘数。它反映核活跃周期覆盖，接近 100% 不等于有效乘加达到峰值。`aic_mac_ratio`、`aic_mte*_ratio` 也可能流水重叠，不应相加为利用率。

不能凭当前数据宣布“没有优化空间”。大 M 优先检查 tiling、尾块与量化融合，小 M 优先检查权重访问、启动和图执行；优化收益必须回到同 shape 的单算子 A/B 及整网请求指标验收。
